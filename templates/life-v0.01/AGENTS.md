# Viventium LIFE — Canonical Agent Rules

This file is the canonical operating contract for Codex, Claude Code, and any other harness working
in this LIFE folder. More specific `AGENTS.md` files may add local instructions but may not weaken
the privacy, evidence, or confirmation rules below.

## Orient before acting

1. Read this file and `CURRENT.md`.
2. Read the closest relevant area or project `README.md`.
3. Inspect only the smallest relevant LIFE slice before expanding.
4. Treat a newer explicit current document or accepted decision as authoritative over older
   history, while preserving the older evidence and supersession trail.

Access to an organized LIFE folder is not permission to inject the whole folder into every turn.

## Protect the person and the evidence

- Default unknown personal material to private.
- Never copy private content into public artifacts, external prompts, logs, screenshots, or QA.
- Never store passwords, OAuth tokens, API keys, cookies, private keys, or secret-bearing URLs here.
- Credentials belong in the operating-system keychain or Viventium runtime configuration.
- Keep facts, assumptions, decisions, tests, results, corrections, and remaining uncertainty
  distinct. A model-generated conclusion is derived until the user accepts it.
- Never interpret an unavailable source or failed retrieval as proof that no evidence exists.
- High-stakes health, legal, financial, safety, and relationship changes default to a proposal.
- Do not send, publish, share, buy, delete, deploy, or make another irreversible external change
  without explicit authority for that action.
- Never request, fabricate, persist, or display hidden chain-of-thought.

## Work naturally in conversation mode

A Viventium conversation running through a harness is an ordinary ongoing conversation, not a
delegated GlassHive mission. Answer naturally, ask a concise clarifying question when it is truly
needed, inspect files, and use native tools when they help.

Work from this exact selected directory. Create or edit user work here only when the user's task
calls for it. Do not create `CLAUDE.md`, `CODEX.md`, harness prompts, mission folders, receipts,
evidence scaffolds, runtime logs, transcripts, `.git`, or a `FINAL REPORT:` block merely because the
conversation is harness-backed. GlassHive transcripts, execution metadata, context manifests, and
authentication state belong in Viventium's private Application Support state.

Full access does not remove the user's authority. Before a destructive, irreversible, externally
consequential, or permission-expanding action, verify that it is explicitly within the request and
pause for approval when it is not.

## Put durable material in one clear place

| Material | Canonical destination |
|---|---|
| Current priorities and active map | `CURRENT.md` |
| Identity, values, preferences, methods | `Self/` |
| People and relationships | `People/` |
| Domain evidence and decisions | `Health/`, `Legal/`, `Finance/`, `Home/`, or `Learning/` |
| Outcome-oriented work | `Projects/<project>/` |
| Cross-project commitments and routines | `Plans/` |
| Communication views | `Communications/` |
| Calendar and event context | `Calendar/` and `Events/` |
| Places and travel context | `Places/` |
| Photo and video indexes | `Media/` |
| User-approved episodic summaries | `Memory/` |
| Ideas, patterns, risks, opportunities, questions | matching `Insights/` folder |
| Reusable skills and capability inventory | `Skills/` and `Tools/` |
| Source and service descriptions | `Sources/` and `Services/` |
| Generated dashboards and indexes | `Views/` |
| Decisions and superseded history | `Decisions_and_History/` |
| Deliberately inactive retained material | `Archive/` |
| Private LIFE bookkeeping | `99_System/` |

Do not create generic `output/`, `final/`, `misc/`, or `tmp/` roots. Put user-facing work in its
actual project or domain and retain source references when a claim depends on outside evidence.

## Finish honestly

Before reporting completion:

- Re-read the request and inspect every claimed deliverable as a user would.
- Confirm important claims trace to evidence and that facts remain distinct from assumptions.
- Confirm no secrets, private leakage, unrelated content, runtime scaffolding, or duplicate roots
  were introduced.
- State what was completed, what was not run, any remaining blocker, and any action still needing
  approval.
