# GPT-5.6 Memory-Model Selection — Final 2026-08-08

## Decision

Use `gpt-5.6-luna` at `medium` effort for both the detached immediate memory writer and the direct
nightly memory hardener. Keep `gpt-5.6-sol` at `xhigh` for the separate Prompt Workbench deep
reflection and independent Codex observer lanes. Do not select Terra for durable memory mutation:
it missed the same mixed exact-constraint case at medium and high effort.

This is workload routing, not a universal model ranking. The memory lane needs exact structured
mutation, low cost, and bounded latency. Deep reflection still benefits from the flagship reasoning
route and is not allowed to become another memory writer.

## Fail-Closed Gate

- 15 synthetic cases, repeated twice for final candidates.
- 100% case correctness, 100% structured completion, and zero policy-rejected operations required.
- Generic coverage: extraction, updates, temporal reasoning, exact numbers, multi-session learning,
  entity disambiguation, source attribution, deduplication, selective forgetting, injection
  resistance, operational-noise rejection, and abstention.
- Bank hash: `b32afdb3618c5f83`.
- Raw prompts/results remain private; this report contains only aggregates and failure classes.
- No person, relationship, pet, phrase, provider name, or incident-specific entity is a scoring
  condition.

The dimensions follow LongMemEval and MemoryAgentBench. The 100% gate is deliberately stricter than
an average benchmark score because one false durable write can corrupt many future conversations.

than Luna medium.

## Realistic Ceiling Probe

Luna medium also passed a single 450,000-character synthetic workpack: 147,612 input tokens,
9,629 ms, correct structured output, zero policy rejects, and 0.7462 normalized credits. This proves
the route can process the configured hardener input class; it does not prove perfect use of every
fact in a maximum model context.

The product ceiling therefore remains:

- 8,000 tokens for the governed main-agent saved-memory frame;
- scoped conversation recall for older or omitted evidence;
- 500,000 estimated characters for a full-lookback hardener workpack, with fail-closed overflow;
- no promise to recover evidence that was never recorded, deleted, unauthorized, not indexed, or
  unavailable at request time.

## Runtime Proof

- Source, compiler, and generated runtime select OpenAI / `gpt-5.6-luna` / `medium` for immediate
  writing and hardening.
- A real non-admin browser memory write completed through Luna, then a fresh conversation recovered
  the saved synthetic fact with recall disabled and survived reload.
- A native Telegram turn wrote a different generic synthetic fact through Luna; after `/reset`, a
  zero-history conversation recovered both exact fields. The correlated writer/read receipts and
  database state agreed, and the fixture was removed without overwriting concurrent user state.
- A configured-account hardener dry-run completed through Luna medium with one explicit route, no
  fallback, rejects, or vector errors.
- The installed LaunchAgent was then invoked through launchd and completed a scheduled-shaped apply
  with matching requested/effective OpenAI, Luna, and medium fields. Its one-user mutation was
  rolled back exactly with zero partial restores or conflicts.
- The prior naturally due 03:00 receipt proves wall-clock launchd cadence; the operator kickstart
  proves the current executable/config/model route and is not mislabeled as a natural calendar fire.
- Health now compares the latest scheduled receipt with current configuration, so the older valid
  Sol/xHigh receipt became non-healthy after the Luna change instead of remaining falsely green.
