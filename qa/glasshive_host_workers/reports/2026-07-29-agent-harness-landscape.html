What changed the decision

These are the deltas that matter more than raw star counts. “Observed” means directly verified in a first-party source; “inference” is a Viventium-specific judgment.

01 · Observed

Google replaced the consumer Gemini CLI path

Google stopped free, Pro and Ultra Gemini CLI requests on 18 June 2026 and directed consumers to Antigravity CLI. Enterprise and API-key Gemini CLI access remains supported.

02 · Observed + secondary

Grok Build is powerful—and security-gated

xAI published a broad Apache-2.0 Rust harness on 15 July. A credible pre-release traffic analysis reported bulk upload of a tracked repository and history; current source adds opt-outs, disabled-by-default product telemetry, local inference and enterprise ZDR, but a Viventium trial still needs egress proof.

03 · Observed

Copilot CLI is now a serious substrate

It exposes ACP server mode, resume/steer, skills, hooks, MCP, built-in Playwright, subagents, scheduled prompts, local sandboxing and cloud sessions.

04 · Observed

Roo Code is shut down

The once-popular repository was archived on 15 May 2026 and explicitly says the extension was shut down. Historical popularity is not present fitness.

05 · Observed

OpenCowork is not one project

At least four unrelated products use the name. The largest active repository is OpenCoworkAI/open-cowork; opencowork.ai is still waiting for its first usable preview.

06 · Observed

OpenAI’s SDK now overlaps GlassHive

Beta Sandbox Agents add manifest-defined workspaces, local/Docker/hosted clients, snapshots, resume, files, shell, skills and artifacts. This is a pattern benchmark, not a migration trigger.

07 · Inference

ACP is the shortest route to optional workers

OpenCode, Goose, Grok Build, Copilot CLI and multiple other agents expose ACP. A strict GlassHive ACP adapter could reduce per-harness glue without surrendering lifecycle ownership.

08 · Observed + inference

LibreChat’s front door got materially stronger

v0.8.5–v0.8.7 add compaction, skills, subagents, artifacts, code execution, observability, stronger MCP auth and per-tool result events. Upgrade selectively; do not turn it into GlassHive.

09 · Observed + inference

Goose has unusually clean host surfaces

Its official custom-distribution guide documents REST session creation, SSE messages and extension control plus ACP new/load/prompt/cancel, tool events, permissions and MCP injection. That makes it the strongest newly discovered second canary.

Identity checks: Grok Build and “OpenCowork”

The names are easy to misread. These conclusions only use ownership and capability claims that can be tied to the official announcement, repository or product site.

Security lab onlyIdentity resolved

Grok Build

Exact identity: xai-org/grok-build, announced by xAI on 15 July 2026 as its coding-agent harness and TUI.

  • Apache-2.0 first-party Rust source; local inference is supported.
  • Interactive TUI, headless scripting/CI and editor embedding through ACP.
  • Files, edits, commands, web search, checkpoints, sandbox, MCP, skills, plugins, hooks and subagents.
  • Its 23 July workflow layer claims saved pause/resume, a 128-agent normal budget, up to 1,024 agents for large runs and built-in deep research; powerful, but not yet independently benchmarked.
  • Security history: a 14 July secondary traffic analysis reported a 5.10 GiB upload containing the tested tracked repository and Git history. xAI disabled implicated server-side flags; the current open source still contains storage and trace-upload machinery.
  • Current mitigations: product telemetry resolves disabled by default, the coding-data registry defaults to opt-out, local inference avoids hosted model transfer, and xAI documents enterprise Zero Data Retention.
  • 23.3k stars in two weeks is momentum, not maturity.
  • Public tree is a monorepo mirror; external contributions are not accepted.
  • Recommendation: network-contained lab only; require local inference or enterprise ZDR and verify telemetry, coding-data sharing, trace upload and all outbound traffic before any real repository is exposed.

OpenCowork

Exact identity: no single canonical project. The most visible released repository is OpenCoworkAI/open-cowork, distinct from AIDotNet/OpenCowork, opencowork.ai and opencowork.chat.

  • OpenCoworkAI: MIT Electron app, WSL2/Lima execution, skills, MCP, traces and model choice.
  • AIDotNet/OpenCowork is a separate Apache-2.0 .NET project, not a release channel for OpenCoworkAI.

  • Recommendation: copy VM-workspace and approval UX ideas, not the desktop shell.

Borrow these five patterns

Each pattern upgrades GlassHive without introducing another top-level orchestrator.

1. ACP worker adapter

One strict adapter for session start, events, approvals, resume, steer, cancel and artifacts. Validate OpenCode, Goose, Copilot and security-gated Grok against the same contract.

2. Portable workspace manifest

Borrow OpenAI Sandbox Agents’ separation of manifest, sandbox client, live session and saved snapshot. Keep GlassHive as lifecycle owner.

3. Durable task semantics

Borrow LangGraph/PydanticAI rules for checkpoints, interrupts, deterministic replay and idempotent side effects; avoid binding the worker loop to a graph DSL.

4. A2A artifact envelope

Use A2A’s task, status, message and artifact ideas for remote interop while retaining the richer internal GlassHive event/audit model.

5. Policy intervention points

Borrow Microsoft ACS’s fail-closed snapshots at startup, input, model, pre/post tool, output and shutdown. Never infer authority from model prose.

Bonus: LibreChat evidence events

Map per-tool result, context usage, cost and resumable-run cleanup into the existing evidence ledger without coupling persistence stores.

A 90-day decision plan

No migration, no popularity contest. Run one synthetic, public-safe contract across candidates and promote only workers that independently meet Viventium’s Quality + Performance metric. Capability breadth alone never promotes a profile: every path must reach parity with the in-process hand-off path on its own AI.

Week 1

Freeze the worker contract

Fixture: version/capability floor and substrate preflight/recovery before run creation; faithful prompt + files; host and Docker modes; tool/MCP discovery; model/effort projection; persistent workspace/warm resume; steer; cancel; permission pause; artifact; callback; final self-check; failure classification; public-safe redaction.

Weeks 2–3

OpenCode canary

Prefer its server or ACP surface over scraping TUI text. Compare event completeness, session durability, provider neutrality and failure truth against Claude/Codex baselines.

Weeks 4–5

Goose + Copilot CLI canaries

For Goose, compare its REST/SSE and ACP surfaces on new/load/resume, cancellation, permission events, MCP injection and extension lifecycle. For Copilot, prove subscription auth, ACP, sandbox, built-in browser and organization-policy behavior.

Week 6

Grok Build security lab

Use only synthetic repositories inside a network-contained environment. Require local inference or enterprise ZDR; explicitly disable and verify product telemetry, coding-data sharing and trace uploads; capture all egress while testing workflows, ACP, pause/resume and cancellation. No promotion without a clean packet-level audit.

Weeks 7–8

Google Antigravity spike

Opt-in only. Capture data-use settings, server dependency, auth recovery, async subagent lifecycle, local sandbox boundaries, MCP parity and session export. Stop if GlassHive cannot own truth and cancellation.

Weeks 9–10

Protocol and policy hardening

Decide whether ACP becomes a supported adapter. Prototype manifest, persistent-workspace and warm-resume boundaries plus fail-closed policy intervention snapshots without changing existing profiles.

Weeks 11–12

LibreChat selective replay

Reconcile the v0.8.4 baseline, then replay compaction, OTel/readiness, skills/subagents and evidence events behind full browser QA. Treat code interpreter as a separate security gate.

Disconfirming evidence

These findings prevent an attractive feature list from becoming an unearned recommendation.

Closed service dependencies can nullify an “open CLI” advantage
Antigravity’s public repository has changelog/examples but no open-source license and the product uses Google’s server-side harness. Claude Code’s main repository also has no permissive repository license. Treat source visibility and operational portability as separate facts.
Open source does not erase Grok Build’s data-path history
A credible 14 July packet-level analysis reported that a pre-release Grok Build client uploaded the full tested tracked repository and Git history through a storage path, independently of model traffic. xAI disabled implicated server-side flags and current code has safer defaults, opt-out controls, local inference and enterprise ZDR. The remaining storage/trace machinery means the correct Viventium response is verification under network containment—not either blind trust or a blanket permanent ban.
Popularity is easy to misread
OpenClaw’s 384.5k stars reflect a general personal-agent ecosystem, not coding quality. Grok Build’s 23k stars in two weeks show launch velocity, not production durability. Roo’s 24k historical stars did not prevent shutdown.
A full platform can be a worse worker
OpenHands, Agno, Cursor Cloud and coworker desktops include orchestration and lifecycle concepts GlassHive already owns. Nesting them can create two competing sources of session, artifact, permission and completion truth.
Framework durability is not workstation persistence
LangGraph, Temporal-backed PydanticAI and cloud agent runtimes can replay logical steps. They do not automatically preserve browser identity, GUI state, host-native credentials or a user-takeover workstation.
Tool protocols do not guarantee semantic parity
Two ACP or MCP implementations may expose different approval, cancellation, streaming, context and artifact semantics. The GlassHive acceptance contract—not protocol presence—decides compatibility.
OpenCowork claims need a real acceptance run
The largest repo advertises GUI operation while its roadmap still lists computer use as forthcoming. Until a released build passes host/VM/browser/action/recovery checks, it is an idea source, not an integration candidate.
