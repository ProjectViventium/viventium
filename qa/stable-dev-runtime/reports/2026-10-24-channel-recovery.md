# Owned runtime and channel recovery

This checkpoint preserves the approved continuous Text / Telegram / Voice relationship. Main owns conversational output; native workers keep independent durable work. Recovery reuses existing input, final, callback and presentation identities. It does not add a second orchestration layer or change provider choices.

## Regression contract

- Unexpected helper or Core loss recovers through the existing owner/watchdog. Explicit Stop and Quit remain intentional.
- A retained input preserves its original content and authority. A saved accepted result must not launch the same action again.
- Completed production and pending presentation are separate facts. A validated saved final outranks the legacy unfinished display flag.
- A quiet completion still needs its exact receipt. A failed zero-item receipt creates no public retry/removal message or speech.
- Confirmed answer text remains accepted when a file send is uncertain. Commit only confirmed references; do not resend an uncertain file.
- Useful later Cortex/worker results keep their own durable presentation identities and receipts.
- Call task state catches up through the existing keepalive. A recovered task snapshot clears its own warning without losing transcript paging or changing call authority.

The owning requirements remain [interaction delivery](../../../docs/requirements_and_learnings/capabilities/interaction-delivery.md), [voice](../../../docs/requirements_and_learnings/capabilities/voice.md) and [runtime/install/release](../../../docs/requirements_and_learnings/capabilities/runtime-install-release.md).

## Evidence and limits

This is a publication checkpoint, not a new full QA run.

The repair evidence includes actual local helper/Core recovery; real Telegram receipt failure followed by the same saved-final recovery; delivered files and next-turn accepted context; and real RTC speech with native browser work, useful completion, a following spoken turn and normal End. Original captures, prompts, account state and receipts remain private.

Candidate verification includes the affected deterministic owners, compiled API and Voice UI builds, and a failed initial task-snapshot regression case. Tests must consume the candidate's compiled package, not a shared dependency link to another checkout. Resolved callback changes must remain in their original owning catch; identical surrounding text is not enough to locate a change safely.

Test fixtures for an exact admission window must use one captured timestamp. A millisecond skew is invalid input; keep the production identity guard strict and prove both rejection and valid admission. Keep partial service mocks aligned with the actual exported interface; a missing mocked export does not justify a production fallback.

The native transport repair is already in xPerfect's independent runtime contract. Its bounded notification copies preserve the model's full input and journal, tool evidence and scoped file delivery. Its standalone checks remain owned by xPerfect.

Public-network media, hardware-microphone perception, sub-two-second speech and multi-day endurance require their separate acceptance cases. A successful local call, a review, or an HTTP health check does not establish them. Original development trees and private data are preserved during publication.
